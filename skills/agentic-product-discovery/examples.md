# Product discovery — worked examples and provenance

Evidence behind the discovery loop in `SKILL.md`.

The extended worked example — a full visual refinement run from broad concept
through palette, typography, density, navigation, components, and identity —
lives in `references/visual-refinement-worked-example.md`. Read that when
running a visual discovery lane. This file covers where the rest of the loop
came from and how far it has been tested.

## 1. What the visual loop is grounded in

The eight-step visual sequence in §3 Step 5 is a generalization of one real
product's progression: a broad portfolio-dashboard concept narrowed through
palette selection, typography and density comparison, navigation and component
coherence, a sidebar-function decision, and finally identity and logo work, each
round ending in durable specifications rather than chat approvals.

The mechanics that transferred were the *narrowing* ones — labelled alternatives,
permitted synthesis across directions, cumulative invariants, one or two changed
axes per round, and system-wide application after local selection. The specific
outputs of that run (its palette, typeface, and imagery) are deliberately not
part of the guidance; the reference file says so explicitly.

## 2. Cold forward tests

Three cold forward tests exercised the routing behavior, each passing:

- **An open-ended UI concept** produced bounded problem-and-workflow questions
  before any visual styling — the failure mode being tested was jumping to
  mockups before the product question was framed.
- **A settled product with open visual direction** produced labelled, comparable
  directions and a controlled next round, rather than one polished option
  presented for vague approval.
- **A ratified CLI product** exited discovery early and routed to bootstrap,
  which is the correct result when the contract is already closed.

These are synthetic tests of *behavior*. They demonstrate the skill routes and
paces correctly; they are not evidence that the workflow produces better product
outcomes in real use. The distinction matters when weighing this skill's claims
against siblings validated across multiple real delivery cycles.

## 3. Provenance and maintenance

The discovery sequence was synthesized from the surrounding
human-ratification, memory, phase, and evidence disciplines, then exercised
against one real UI product's design progression and the three cold forward
tests above.

Evidence would be materially strengthened by a run against each of: an
open-ended UI product, an API or CLI product where visual discovery should stay
minimal, a bounded feature in the Quick lane, and an already-ratified spec where
the correct outcome is an early exit.

Promote or revise only through `agentic-workflow-evolution`. Preserve rejected
paths and named failure modes rather than rewriting the history.
